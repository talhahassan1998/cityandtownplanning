# Cars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Realistic procedural vehicles in parking areas, in road lanes, at kerbs and in front of buildings, on the project's driving side.

**Architecture:** `three/cars.ts` builds cached per-kind vehicle geometries and shared materials and turns placements into `InstancedMesh`es. `three/traffic.ts` is a pure function from plan features to `CarSpot[]` in local metres. `buildScene` calls both behind `SceneOptions.cars`; settings and UI add the driving side and a Cars toggle.

**Tech Stack:** TypeScript, Three.js 0.186, Turf 7, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-cars-design.md`

## Global Constraints
- Not a git repo: gate per task = `npm test` + `npx tsc` clean; ledger in `.superpowers/sdd/cars/progress.md`.
- No asset files; procedural only. Materials shared (`userData.shared = true`), never mutated/disposed per car.
- Angles: headings in degrees clockwise from east (project convention); local frame e (east), n (north); scene x = e, z = −n.
- Driving side default **left** (`settings.drivingSide` absent = left).
- Max 3000 cars per scene (`ponytail:` cap).
- Static only; cars not pickable.

## Review Focus
- Curved/polyline roads (many vertices): lane offsets must follow each segment's normal, cars not cutting corners off the carriageway — Task 2 test with an L-shaped road.
- Roads with `width` missing/0 or `lanes` 0/1: no NaN positions, no crash; 1-lane road gets cars heading one way only on the driving side — Task 2 test.
- Hand-placed buildings with no road nearby (> 40 m): no driveway car rather than a car floating far away — Task 2 test.
- Terrain on: cars sit at `elevLocal`, never under the draped road (road lift 0.12) — Task 3 asserts car instance y ≥ ground.
- Selection highlight / dispose must skip car materials (shared) — Task 3 test that `dispose()` leaves car materials usable.

### Task 1: Vehicle models (`src/three/cars.ts`)

**Files:** Create `src/three/cars.ts`, `src/three/cars.test.ts`

**Interfaces:**
- Produces:
  - `export type VehicleKind = 'sedan' | 'hatch' | 'suv' | 'bus' | 'truck'`
  - `export const VEHICLE_SIZE: Record<VehicleKind, [number, number, number]>` — L, W, H: sedan [4.6, 1.8, 1.45], hatch [4.0, 1.75, 1.5], suv [4.8, 1.9, 1.8], bus [12, 2.55, 3.2], truck [8, 2.5, 3.4]
  - `export function vehicleParts(kind: VehicleKind): { slot: 'body' | 'glass' | 'tyre' | 'light'; geo: THREE.BufferGeometry }[]` — cached; origin ground centre, length along +z (front +z), width along x.
  - `export function carColor(seed: number): THREE.Color` — white 25%, silver 20%, grey 15%, black 15%, rest red/blue/green/beige.
  - `export interface CarSpot { e: number; n: number; y: number; heading: number; kind: VehicleKind; seed: number }`
  - `export function carMeshes(spots: CarSpot[]): THREE.InstancedMesh[]` — one per kind × slot; body slot gets `setColorAt(carColor(seed))`; heading → rotation.y so that local +z points along the heading (heading 0 = east → +x; heading 90 = south → +z scene). Meshes `castShadow = true`.
- Models: sedan/hatch/suv = lower body box with bevel-like tapered top (bonnet / cabin / boot via 2–3 boxes of different heights, cabin narrower), glass = slightly inset cabin shell, 4 tyres (cylinders r 0.33, w 0.22, rotated on x), head/tail light boxes. Bus = long body + window band + 4 tyres. Truck = cab (2.2 m) + box body.

### Task 2: Placement (`src/three/traffic.ts`)

**Files:** Create `src/three/traffic.ts`, `src/three/traffic.test.ts`; Modify `src/three/models.ts:70-82` (parking: keep bay lines, drop box cars; export bay positions)

**Interfaces:**
- Consumes: `CarSpot`, `VehicleKind`, `VEHICLE_SIZE` (Task 1); `roadSurface`, `frame` (`geo.ts`); `ROAD_CLASSES`, `componentDef`, `type PlanFeature` (`model.ts`); `orientedBox` (`geo.ts`).
- Produces:
  - `export function parkingBays(hx: number, hy: number): [number, number][]` in `models.ts` — the bay centres (box frame) the markings use: x from −hx+1.5 step 2.6, z = ±(hy−2.6); `groundExtras('parking')` uses it for markings only.
  - `export function placeCars(features: PlanFeature[], toLocal: (p: Position) => [number, number], side: 'left' | 'right', ground: (e: number, n: number) => number): CarSpot[]`
- Rules (exact values):
  - seed per feature from a string hash of its id; per-candidate rng from that.
  - parking: each bay with p 0.7, heading perpendicular to the box's long axis (nose to the aisle, i.e. towards box centre line), kind sedan/hatch/suv.
  - lanes on `road-highway|road-arterial|road-collector|road-local` with `structure` not tunnel/bridge: `lanes = max(1, attrs.lanes || ROAD_CLASSES[class].lanes)`, `cw = width − 2·sidewalk` (sidewalk from attrs, else class), lane width `lw = cw / lanes` capped at 3.5 when kerb rows exist (below). Lanes per direction: `ceil(lanes/2)` driving-side, rest opposite (1-lane: only the driving-side direction). Left driving = traffic keeps to the left of its heading; lane centre offset measured along the segment's left normal (n = (−dy, dx)/len in e/n space) → for left driving, forward lanes have positive left-normal offset. Spacing per lane: highway/arterial 25 m, collector 40 m, local 70 m, jitter ±40%. Kind: sedan/hatch/suv; on arterial/collector/highway 1 in 12 is bus or truck.
  - kerb rows (local, collector): `rows = cw ≥ lanes·2.75 + 4.4 ? 2 : cw ≥ lanes·2.75 + 2.2 ? 1 : 0`; one row = driving-side kerb; centre 1.1 m inside the carriageway edge; slots every 6 m, p 0.6; heading = traffic direction of the nearest lane.
  - junction clearance: drop lane/kerb cars whose point is within `12 + otherWidth/2` m of any other road centreline (planar segment distance).
  - building fronts: for buildings (`floors > 0`, polygon) of type house/villa → 1 car; shop/office/mixed-use/clinic/school/community/police/fire/government/library → 1–3; find the nearest road centreline point within 40 m of the footprint centre (else none); the face of `orientedBox` closest to it; car centre 1.2 m outside that face, parallel to it, spaced 5.5 m along it; drop a car if any of its 4 corners lies inside any road surface or any building footprint (local coords).
  - cap 3000: if more, keep every k-th (k = ceil(n/3000)).
  - `y = ground(e, n)` for each spot.

- [ ] **Step 1: Failing tests** (`traffic.test.ts`, features built with `lineAt`/`footprint` from `geo.ts`, identity-ish `toLocal = frame(C).toLocal`, flat ground):
  - straight E–W local street 12 m, 2 lanes, side left: every lane car with heading ≈ 0 (eastbound) has n > 0 (north = left of east), heading ≈ 180 has n < 0; side right → reversed.
  - kerb rows: 12 m local street → some cars at |offset| ≈ 6 − 1.5 − 1.1 = 3.4 (one row only, on the driving side); 9 m local street → no kerb cars.
  - crossing N–S road at the middle: no lane/kerb car within 12 + width/2 m of it.
  - L-shaped local street (two segments): every lane car lies within the road surface (`booleanPointInPolygon` on the local surface).
  - road with `lanes: 1, width: 6`: all lane cars head the same way; road with width 0 → `[]` for it, no NaN anywhere.
  - house 10×12 with a local street 9 m from its front: exactly one car, corners outside the house and outside the road surface; same house with no road within 40 m → no car.
  - parking 40×25: count ≈ 0.7 × `parkingBays(20, 12.5).length` (±40%), all inside the parking box.
  - determinism: two calls equal; 2 km arterial grid producing > 3000 candidates → length ≤ 3000.
  - rail / cycle / bridge roads → no cars.
