# Edit in 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drag objects across the ground, rotate them with a ring handle, and drop library components into the 3D city view.

**Architecture:** Pure helpers in `three/edit3d.ts` (movability, ring angle) plus `BuiltScene.toGeo`; one new store action `moveFeatures`; `CityView.tsx` gets a small pointer state machine that previews by moving the selection's meshes and commits once on release (existing `rotateFeatures` for rotation, `addFeature` for drops).

**Tech Stack:** TypeScript, React, Three.js 0.186, Zustand + zundo, Vitest; headless Playwright for the browser check.

**Spec:** `docs/superpowers/specs/2026-10-19-edit-in-3d-design.md`

## Global Constraints
- Not a git repo: gate per task = `npm test` + `npx tsc` clean; ledger `.superpowers/sdd/edit-in-3d/progress.md`.
- One undo step per drag/rotate/drop; no store writes during a drag.
- Movable = spec's `isMovable` list only; locked layers (`lockedIds`) never move.
- No editing in walk mode. Click (< 4 px movement) keeps today's select behaviour.
- Angles: degrees clockwise (matches `rotateFeatures`, which rotates each feature about its own centre).
- Use lucide icons / existing classes for any UI; status text in the existing 3D status line.

## Review Focus
- A drag that starts on a selected object but whose selection also contains a road/plot: only movable, unlocked members move; the rest stay — Task 2 test.
- Pointer leaves the canvas mid-drag (pointerup outside): the drag must still end and commit (use pointer capture) — Task 3 browser step.
- Scene rebuild arriving mid-drag (e.g. autosave/other edit): meshes are replaced; the drag must cancel cleanly, not throw — Task 3 code note + browser step.
- Drop on the sky (no ground hit): nothing is added — Task 1 `groundHit` returns null test.
- Rotation across the ±180° seam: no 360° jump — Task 1 `ringAngle` wrap test.

### Task 3: CityView interaction (drag, ring, drop) + browser check + docs

**Files:** Modify `src/three/CityView.tsx`; README (3D section), `.claude/CLAUDE.md`, memory.

**Interfaces:** Consumes Tasks 1–2, `rotateFeatures`, `addFeature`, `componentGeometry`/`componentDef` (as in `MapCanvas.onDrop`), `snapToGrid` with `s.snap` (as in MapCanvas).

Behaviour (exact):
- `pointerdown` (not walk, left button): raycast pickables; if the hit id is in the selection and the movable∩unlocked selection is non-empty → start **move**: `orbit.enabled = false`, `setPointerCapture`, remember start ground point (`groundHit` with the terrain mesh) and, for every mesh whose `userData.id` is in the moving set, its start position. If instead the ray hits the ring mesh → start **rotate** (same capture/orbit handling).
- `pointermove`: move → offset = ground point − start (x/z); with `snap.grid` snap the selection centre (`toGeo`→`snapToGrid`→`toScene`) and derive the offset from it; set each mesh's position = start + offset, y += `groundAt(new) − groundAt(old)` of the mesh's own bbox centre. Rotate → `deg = ringAngle(centre, startPt, pt, e.shiftKey)`; rotate each moving mesh about its own feature centre by −deg (scene y-rotation is counter-clockwise from above); status line shows `Rotate ${deg}°`.
- `pointerup`: release capture, `orbit.enabled = true`; if moved < 4 px → treat as today's click; else commit once: move → `moveFeatures(ids, dEast, dNorth)` computed from `toGeo` of start/end centres in metres (local frame: dx = Δx, dy = −Δz); rotate → `rotateFeatures(ids, deg)` when deg ≠ 0. The store change triggers the normal rebuild.
- Rebuild while dragging: the rebuild function cancels any active drag first (drop references, re-enable orbit).
- Ring: `THREE.RingGeometry(r, r + 1.2, 64)` laid flat at the selection centre (`groundAt + 0.3`), accent `#00e5ff`, `depthTest: false`, renderOrder high; r = max horizontal half-extent of the movable selection's meshes + 4 m; shown only when the movable selection is non-empty and the camera is not walk; updated on selection change and after rebuild; excluded from `pickables`/selection picking (separate raycast target).
- Drop: container gets `onDragOver={(e) => e.preventDefault()}` and `onDrop`: type from `application/x-urbanforge`; `groundHit` at the drop point; null → ignore; else `c = toGeo(hit)` (grid-snapped if on), `s.setTool('select')`, `id = s.addFeature(type, componentGeometry(componentDef(type), c))`, `s.select([id])`.
